# Capability Evolution Map

Role: `authoritative` seed capability evolution map.

Seed mode can record gaps and draft inactive proposals.

Read:

1. `gaps.md`
2. `proposals/lead-qualification.md`
3. `proposals/service-qa.md`
4. `proposals/estimate-packet-preparation.md`
5. `proposals/payment-capability.md`
6. `proposals/customer-property-memory-specialist.seed.md`
7. `gap-types.md`
8. `gap-record.schema.json`

No capability is approved or activated at seed initialization.

Activation requires owner approval, runtime support, registry updates, prompt guidance, output contract, facet policy, eval coverage, and a lifecycle transition.

Self-inspection (`semfs_inspect_identity` / `pnpm inspect`) can record structural and governance findings about gaps and proposals. V1 inspection does not auto-repair or activate anything.
